# 外贸信息判定参考(references/trade-judgement.md)

给 Agent 的理解层规则:怎么识别客户、怎么提取事实、怎么定待办、什么时候必须标待确认。

## 客户识别(从严)

按强度递减,取最可靠的一个来源,交叉印证:

1. **公司域名邮箱**:`marco.rossi@casarossi.it` + 签名/正文出现 Casa Rossi Mobili → 高置信。
2. **签名块**:姓名 + 公司 + 地址/电话,与域名一致 → 高置信。
3. **正文自称**:"I am purchasing manager at X" → 高置信,记录职务。
4. **只发件人显示名**("David")或免费邮箱(gmail/qq/163 等,脚本已标 `free_domain: true`)→ **低置信**:
   - 能通过历史邮件/域名/上下文确证 → 照常建档;
   - 不能确证 → `map-customer --unconfirmed`,档案 `unconfirmed: true`,「待确认」章节写明核实点(公司名、采购型号、是否老客户);
   - **禁止因为"看着像某个老客户"就并入已有档案**——并入必须基于邮箱地址或用户明确确认。

同一客户换了邮箱/多人同公司:多个地址可映射到同一 slug(map-customer 支持逗号分隔);对端不同联系人是否同一客户拿不准 → 各自建档并在档案里互相提及,不合并。

## 阶段判定(外贸常见漏斗)

询盘 Inquiry → 报价 Quote → 还价 Negotiation → 样品 Sample → PI/形式发票 → 付款 Terms/Deposit → 生产 Production → 出货 Shipment → 售后 After-sales / 投诉 Complaint → 复购 Re-order

档案「当前阶段」写漏斗中最靠后的**有邮件证据的阶段**,后跟日期。客户接受价格 ≠ 订单成立,除非原文确认下单/要求 PI/提及 PO。

## 关键事实(必须带 [msg-<id>] 出处)

| 类别 | 提取要点 |
| --- | --- |
| 产品 | 型号/规格/材质,保留原文写法(如 NP-104、WT-118) |
| 数量 | 数值 + 单位 + 是"预计"还是"确认" |
| 价格 | 数值 + 币种 + 贸易术语(FOB 上海/青岛)+ 有效期;还价历史按时间保留 |
| 交期 | 天数或日期,区分"生产周期"与"最迟交付" |
| 付款 | T/T 30/70、L/C at sight 等,原文写法 |
| 承诺 | 我方答应的(寄样、换货、证书)与客户答应的(下单、付款、来访)分开记 |
| 投诉 | 批次号、缺陷率、客户要求;投诉是最高优先级事实 |

**矛盾处理**:同字段出现新旧值,以时间新的为准;档案里保留旧值与两个出处(例:价格 18.40→19.10 [msg-a] [msg-b])。这是"价格涨了"的证据链,不能只写新值。

## 下一行动(每封邮件必问)

"现在谁欠谁一个动作?" 三分类,**每条给依据**:

- **业务员做**:报价/还价答复、寄样、发 PI、处理投诉、发证书、确认排产。触发词:问价、问交期、要样品、投诉、要文件。
- **等客户**:确认预算/PO、回 PI、付定金、发 defect 照片、确认来访日期。触发词:next week 确认、will send、awaiting。
- **日历事件**:来访、验货、展会的明确日期——写进档案,不是待办。

没有动作的邮件(纯寒暄、通知)→ 不产生待办,只进进展。

## 待确认(不编造的兜底)

以下情况**必须**进档案「待确认」章节,并视性质在 tasks.md 加一条"向客户确认"待办:

- 身份:免费邮箱 + 无公司信息(inbox 来源的 `free_domain: true` 且无佐证)。
- 事实:金额/数量模糊("same as last time" 但无法确定指哪单)、语种翻译不确定、引用了不存在的附件。
- 归属:同一邮件可能涉及两个客户;新邮箱与老客户关系存疑。

写法:`- <问题> —— 依据 [msg-<id>]`,不要写猜测结论。

## 语言

原文是英文的关键值(型号、价格条款、公司名)保留英文;叙述用中文。用户邮件是其他语种且翻译无把握 → 原文摘录 + 待确认。

## 事实严格化(v3,来自真实邮箱实验的教训)

以下判断规则是硬性的,违反即"编造":

1. **报价 vs 指示价**:只有明确写出价格/条款/有效期并承诺按此执行的,才算"正式报价";"大约/大概/预算价/target price/price idea" 一律记为指示价,并注明原文措辞。
2. **预计日期 ≠ 确定交期**:"expected delivery / 估计 X 天"与合同性承诺分开记;只有 PI/订单/我方书面承诺里的日期才算硬性交期。
3. **已发 = 已行动**:我方已发出的邮件(报价、确认、承诺)必须记为"我方已行动",不得在任何状态里把该事项继续当作"未回复/待办"。已发邮件的时间线永远保留出处。
4. **品牌/公司/国家不凭图片或文件名认定**:附件名"Milano_showroom.png"或图片里有 Logo 不能证明客户公司/国家;这些字段只来自邮件正文/签名/域名,或用户确认。证据不足 → 待确认。
5. **部分覆盖不推断全史**:只拉取了近 60 天邮件时,禁止写"客户至今未付款/未回复";只能写"导入范围内未见到"。覆盖范围以 render 写入的覆盖声明为准。
6. **待办关闭**:同一客户新事实到达后,已完成的待办必须关闭(`- [x]`)或替换,不能在概览/下一行动里继续堆积过期事项。待办的有效性以最新邮件为准。
7. **证据不足一律待确认**,不得用常识补齐:宁可空着 + 待确认,不写"应该是"。
